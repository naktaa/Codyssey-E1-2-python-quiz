# 상식 퀴즈 게임 아키텍처 및 구현 계획

## 문서 목적

이 문서는 E1-2 상식 퀴즈 게임의 확정된 구조, 동작 기준, 구현 순서와
Git 커밋 경계를 기록한다. 실제 구현과 검증 결과가 이 계획과 달라지면
현재 코드와 실행 결과를 우선하고 관련 진행 문서를 갱신한다.

## 범위와 기본 결정

- 퀴즈 주제는 여러 카테고리로 구성된 상식 퀴즈다.
- 플레이할 때 전체 문제를 섞지 않고 한 카테고리를 선택한다.
- 카테고리 목록은 퀴즈의 `category` 값에서 자동으로 만든다.
- 최고 점수는 카테고리별 0 이상의 누적 점수로 저장한다.
- 실제 기본 문제는 과학 3개와 역사 2개, 총 5개다.
- 외부 라이브러리 없이 Python 표준 라이브러리만 사용한다.
- 랜덤 출제, 힌트, 문제 수 선택, 퀴즈 삭제와 점수 히스토리는 필수 기능
  완료 후 승인받아 진행할 보너스 범위다.

## 프로그램 구조

```text
main.py
   │
   ▼
src/game_manager.py
└── QuizGame
   ├── Quiz 객체 목록
   ├── 카테고리별 최고 점수
   ├── 메뉴와 공통 입력
   ├── 플레이·추가·목록·점수
   └── state.json 저장·불러오기
           │
           ├── 정상 데이터
           └── src/default_quizzes.py fallback
```

애플리케이션 코드는 `src/`에 둔다. 기존 `tests/`는 과거 개발 기록으로만
유지하며 2026-08-05 이후 실행하거나 수정하지 않는다. `main.py`는 실행 명령을
단순하게 유지하기 위해 루트에 두고, 최종 `state.json`도 미션 요구사항에 따라
프로젝트 루트에 둔다.

### `main.py`

- 프로그램 진입점만 담당한다.
- `get_state_path()`로 실제·확인용 상태 경로를 선택한다.
- 확인용 모드이면 사용할 파일을 안내한다.
- `QuizGame` 객체를 만들고 `load_state()` 후 `run()`을 호출한다.

### `Quiz`

```python
Quiz(
    category: str,
    question: str,
    choices: list[str],
    answer: int,
)
```

책임:

- 카테고리, 문제, 선택지 4개와 정답 번호 보관
- 빈 문자열, 선택지 개수와 정답 범위 검증
- 문제와 선택지 출력
- 사용자 답의 정오답 확인
- `to_dict()`와 `from_dict()`를 통한 JSON 변환

검증 기준:

- 카테고리와 문제는 공백 제거 후 비어 있을 수 없다.
- 선택지는 정확히 4개이며 각 선택지는 비어 있을 수 없다.
- 정답은 1~4 범위의 정수다.

### `QuizGame`

주요 속성:

```python
quizzes: list[Quiz]
best_scores: dict[str, int]
state_path: Path
```

주요 메서드:

- `run()`
- `show_menu()`
- `read_int()`
- `read_nonempty()`
- `get_categories()`
- `select_category()`
- `select_quiz_count()`
- `ask_for_hint()`
- `show_hint()`
- `play_quizzes()`
- `add_quiz()`
- `list_quizzes()`
- `delete_quiz()`
- `show_best_scores()`
- `load_state()`
- `save_state()`
- `validate_state_data()`
- `backup_corrupted_state()`
- `recover_corrupted_state()`
- `safe_exit()`

게임 로직은 저장 경로, 입력 함수와 출력 함수를 선택적으로 주입할 수 있다.
현재 직접 기능 확인은 `QUIZ_STATE_MODE=test`로 `state.test.json`을 선택해 실제
`state.json`과 분리한다.

## 메뉴와 기능 흐름

```text
1. 퀴즈 풀기
2. 퀴즈 추가
3. 퀴즈 목록 보기
4. 카테고리별 최고 점수
5. 퀴즈 삭제
6. 종료
```

### 퀴즈 풀기

1. 퀴즈가 있는 카테고리를 번호 목록으로 표시한다.
2. 사용자가 한 카테고리를 선택한다.
3. 해당 카테고리의 전체 문제 수 안에서 풀 개수를 선택한다.
4. `random.sample()`로 선택한 개수만큼 중복 없이 뽑는다.
5. 반환된 무작위 순서대로 출제하며 원본 목록과 JSON 순서는 유지한다.
6. 문제마다 힌트 사용 여부를 선택한다.
7. 힌트는 정답과 무작위 오답 하나를 두 개의 후보로 표시한다.
8. 답을 입력할 때마다 정답 또는 오답과 실제 정답을 안내한다.
9. 힌트 없이 정답이면 3점, 힌트 사용 후 정답이면 1점, 오답이면 0점을 더한다.
10. 완료 후 정답 수, 힌트 사용 횟수와 `획득 점수/출제 수 × 3점`을 출력한다.
11. 카테고리별 최고 점수를 비교하고 저장한다.

퀴즈가 없으면 안내 후 메인 메뉴로 돌아간다.

### 퀴즈 추가

- 카테고리 이름을 직접 입력한다.
- 기존 이름과 같으면 같은 카테고리로 묶고 새 이름이면 새 카테고리를 만든다.
- 문제, 선택지 4개와 정답 번호를 입력받는다.
- 모든 값이 정상일 때만 `Quiz`를 목록에 추가한다.
- 정상 추가 직후 활성 상태 파일에 저장한다.
- 환경 변수 미지정 또는 `real` 모드에서는 `state.json`, `test` 모드에서는
  `state.test.json`을 사용한다.
- 입력 도중 중단되면 불완전한 퀴즈를 저장하지 않는다.

### 퀴즈 목록

- 저장된 퀴즈를 카테고리별로 묶어 표시한다.
- 각 문제와 선택지를 확인할 수 있게 한다.
- 퀴즈가 없으면 별도 안내 후 메뉴로 돌아간다.

### 퀴즈 삭제

- 카테고리와 해당 카테고리의 문제 번호를 선택한다.
- 선택한 문제 내용을 다시 표시하고 삭제 또는 취소를 입력받는다.
- 삭제를 확인한 경우에만 목록에서 제거하고 활성 상태 파일에 즉시 저장한다.
- 해당 카테고리의 마지막 문제가 삭제되면 더 이상 표시할 수 없는 최고 점수도
  함께 제거한다.
- 파일 저장에 실패하면 메모리의 퀴즈와 최고 점수도 삭제 전 상태로 되돌린다.

### 최고 점수

- 문제별 획득 점수를 합산하고 만점은 `출제 문제 수 × 3점`으로 계산한다.
- 힌트 사용 횟수는 정답 여부와 관계없이 실제로 힌트를 본 횟수를 센다.
- 기존 카테고리 점수보다 높을 때만 최고 점수를 갱신한다.
- 갱신한 점수는 즉시 `state.json`에 저장한다.
- 아직 플레이하지 않은 카테고리는 `기록 없음`으로 표시한다.
- 이전 100점 환산 기록은 형식상 유효하므로 자동 변환하거나 삭제하지 않는다.
  새 방식 확인 시 확인용 상태의 `best_scores`를 비워 서로 다른 기준을 분리한다.

## 공통 입력과 안전 종료

- 입력 앞뒤의 공백을 제거한다.
- 빈 입력, 숫자 변환 실패와 범위 밖 입력은 안내 후 다시 받는다.
- 카테고리, 문제와 선택지에는 빈 문자열을 허용하지 않는다.
- 숫자가 필요한 메뉴, 답 선택과 정답 등록에 같은 검증 메서드를 사용한다.
- `KeyboardInterrupt`와 `EOFError`는 가능한 상태를 저장한 뒤 traceback 없이
  안내 메시지와 함께 종료한다.

## `state.json` 스키마

카테고리별 최고 점수를 사용하므로 단수 `best_score` 대신 일관되게
`best_scores`를 사용한다.

```json
{
  "quizzes": [
    {
      "category": "과학",
      "question": "문제 내용",
      "choices": ["선택지 1", "선택지 2", "선택지 3", "선택지 4"],
      "answer": 1
    }
  ],
  "best_scores": {
    "과학": 7
  }
}
```

- 프로젝트 루트를 기준으로 경로를 계산한다.
- 기본값과 `QUIZ_STATE_MODE=real`은 `state.json`, `QUIZ_STATE_MODE=test`는
  Git에서 제외한 `state.test.json`을 사용한다.
- UTF-8, `ensure_ascii=False`, 들여쓰기 2칸으로 저장한다.
- 임시 파일을 먼저 작성한 뒤 교체하여 부분 저장을 방지한다.
- 파일이 없으면 기본 퀴즈와 빈 최고 점수로 시작한다.
- JSON 문법이나 스키마가 손상되었으면 timestamp가 붙은 파일로 원본을
  백업한 뒤 기본 상태를 만든다.
- 백업에 실패하면 원본을 덮어쓰지 않고 메모리 상태로 실행한다.
- 읽기·쓰기 오류는 `try/except`로 처리하고 사용자에게 안내한다.
- 손상 파일 백업은 Git에 실수로 추가되지 않도록 제외한다.

### 오류 원인 메시지

- `validate_state_data()`는 최상위 객체, `quizzes`, `best_scores`와 점수 형식에
  대해 코드에 정의된 `ValueError` 메시지를 발생시킨다.
- `Quiz.from_dict()`와 `Quiz.__post_init__()`은 개별 퀴즈의 필수 필드,
  문자열·선택지·정답 형식 오류 메시지를 담당한다.
- `load_state()`는 위 오류를 잡아 `상태 파일이 손상되었습니다: {오류}` 형식으로
  출력한 뒤 복구를 시작한다.
- JSON 문법 오류의 세부 내용은 표준 라이브러리 `json`의
  `JSONDecodeError`, 파일 입출력 오류 내용은 `OSError.strerror`에서 가져온다.

## 단계별 구현과 Git 커밋

각 단계는 사용자 직접 실행과 필요한 증거를 확인한 뒤 커밋한다. 한 번에 한
단계만 진행하며 push는 별도 요청 전까지 수행하지 않는다. unittest는 더 이상
실행하거나 수정하지 않는다.

1. 계획 문서 저장
   - `Docs: 상식 퀴즈 구현 계획 정리`
2. 메뉴와 공통 입력
   - `Feat: 메뉴와 공통 입력 처리 구현`
3. `Quiz` 클래스와 카테고리 데이터 구조
   - `Feat: Quiz 클래스와 카테고리 구조 구현`
4. `feature/solving` 브랜치에서 카테고리별 플레이
   - `Feat: 카테고리별 퀴즈 플레이 구현`
5. `main`에 `--no-ff` 병합
6. 퀴즈 추가
   - `Feat: 퀴즈 등록 기능 구현`
7. 퀴즈 목록
   - `Feat: 퀴즈 목록 조회 기능 구현`
8. 카테고리별 최고 점수
   - `Feat: 카테고리별 최고 점수 구현`
9. `QuizGame` 책임 정리
   - `Refactor: QuizGame 기능별 책임 정리`
10. `state.json` 입출력 완성
    - `Feat: state.json 저장과 불러오기 구현`
11. 통합 예외와 안전 종료
    - `Fix: 입력 중단과 손상 데이터 복구 처리`
12. 직접 실행과 영속성 검증
    - `Docs: 필수 기능과 데이터 영속성 검증 기록`
13. 사용자가 제공한 상식 퀴즈 5개 이상 반영
    - `Feat: 상식 퀴즈 기본 데이터 추가`
14. README와 제출 증거 정리
    - `Docs: README와 제출 증거 정리`

퀴즈 플레이 브랜치 작업 시 다음 명령을 사용한다.

```zsh
git status --short --branch
git checkout -b feature/solving
# 기능 구현, 검증과 커밋
git checkout main
git merge --no-ff feature/solving
git log --oneline --graph --decorate --all
```

`--no-ff`로 fast-forward가 가능한 경우에도 병합 커밋을 남긴다. 병합과
그래프를 확인하기 전에는 기능 브랜치를 삭제하지 않는다.

## 검증 계획

### 사용자 직접 실행과 증거

- 메뉴 1~6과 잘못된 입력
- 기존·신규 카테고리 퀴즈 추가
- 퀴즈 목록, 정오답과 최종 결과
- 최고 점수 확인
- 종료 후 재실행 데이터 유지
- 손상 파일 백업과 기본 상태 복구
- Git 브랜치 분기와 `--no-ff` 병합 그래프

검증된 터미널 결과와 화면만 `evidence/`에 저장한다.

### 문서·정적 확인

- `git status --short --branch`로 브랜치와 변경 파일 확인
- `git log --oneline --graph --decorate --all`로 실제 Git 이력 확인
- `git diff --check`로 문서와 코드의 공백 오류 확인
- import 목록으로 Python 표준 라이브러리만 사용하는지 확인

정적 확인은 실행 기능의 정상 증거를 대신하지 않는다. 기능 완료 표시는 사용자가
`main.py`를 직접 실행한 원본 로그나 캡처와 연결한다.
