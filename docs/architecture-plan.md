# 상식 퀴즈 게임 아키텍처 및 구현 계획

## 문서 목적

이 문서는 E1-2 상식 퀴즈 게임의 확정된 구조, 동작 기준, 구현 순서와
Git 커밋 경계를 기록한다. 실제 구현과 검증 결과가 이 계획과 달라지면
현재 코드와 실행 결과를 우선하고 관련 진행 문서를 갱신한다.

## 범위와 기본 결정

- 퀴즈 주제는 여러 카테고리로 구성된 상식 퀴즈다.
- 플레이할 때 전체 문제를 섞지 않고 한 카테고리를 선택한다.
- 카테고리 목록은 퀴즈의 `category` 값에서 자동으로 만든다.
- 최고 점수는 카테고리별 0~100점으로 저장한다.
- 실제 기본 문제는 사용자가 나중에 제공하며, 그전에는 임시 문제 4개와
  테스트 전용 fixture로 구조와 기능을 검증한다.
- 외부 라이브러리 없이 Python 표준 라이브러리만 사용한다.
- 랜덤 출제, 힌트, 문제 수 선택, 퀴즈 삭제와 점수 히스토리는 필수 기능
  완료 후 승인받아 진행할 보너스 범위다.

## 프로그램 구조

```text
main.py
   │
   ▼
src/game_manager.py
└── QuizGame
   ├── Quiz 객체 목록
   ├── 카테고리별 최고 점수
   ├── 메뉴와 공통 입력
   ├── 플레이·추가·목록·점수
   └── state.json 저장·불러오기
           │
           ├── 정상 데이터
           └── src/default_quizzes.py fallback
```

애플리케이션 코드는 `src/`, 자동 테스트는 `tests/`에 둔다. `main.py`는
실행 명령을 단순하게 유지하기 위해 루트에 두고, 최종 `state.json`도 미션
요구사항에 따라 프로젝트 루트에 둔다.

### `main.py`

- 프로그램 진입점만 담당한다.
- `src.game_manager`의 `QuizGame` 객체를 `game_manager` 변수로 생성하고
  `run()`을 호출한다.

### `Quiz`

```python
Quiz(
    category: str,
    question: str,
    choices: list[str],
    answer: int,
)
```

책임:

- 카테고리, 문제, 선택지 4개와 정답 번호 보관
- 빈 문자열, 선택지 개수와 정답 범위 검증
- 문제와 선택지 출력
- 사용자 답의 정오답 확인
- `to_dict()`와 `from_dict()`를 통한 JSON 변환

검증 기준:

- 카테고리와 문제는 공백 제거 후 비어 있을 수 없다.
- 선택지는 정확히 4개이며 각 선택지는 비어 있을 수 없다.
- 정답은 1~4 범위의 정수다.

### `QuizGame`

주요 속성:

```python
quizzes: list[Quiz]
best_scores: dict[str, int]
state_path: Path
```

주요 메서드:

- `run()`
- `show_menu()`
- `read_int()`
- `read_nonempty()`
- `get_categories()`
- `select_category()`
- `play_quizzes()`
- `add_quiz()`
- `list_quizzes()`
- `show_best_scores()`
- `load_state()`
- `save_state()`
- `safe_exit()`

테스트에서 실제 프로젝트의 `state.json`과 터미널을 사용하지 않도록 저장
경로, 입력 함수와 출력 함수를 선택적으로 주입할 수 있게 한다.

## 메뉴와 기능 흐름

```text
1. 퀴즈 풀기
2. 퀴즈 추가
3. 퀴즈 목록 보기
4. 카테고리별 최고 점수
5. 종료
```

### 퀴즈 풀기

1. 퀴즈가 있는 카테고리를 번호 목록으로 표시한다.
2. 사용자가 한 카테고리를 선택한다.
3. 해당 카테고리의 문제를 저장된 순서대로 모두 출제한다.
4. 답을 입력할 때마다 정답 또는 오답과 실제 정답을 안내한다.
5. 완료 후 정답 수, 전체 문제 수와 100점 환산 점수를 출력한다.
6. 점수 기능이 연결된 뒤 카테고리별 최고 점수를 비교하고 저장한다.

퀴즈가 없으면 안내 후 메인 메뉴로 돌아간다.

### 퀴즈 추가

- 카테고리 이름을 직접 입력한다.
- 기존 이름과 같으면 같은 카테고리로 묶고 새 이름이면 새 카테고리를 만든다.
- 문제, 선택지 4개와 정답 번호를 입력받는다.
- 모든 값이 정상일 때만 `Quiz`를 목록에 추가한다.
- 현재 등록 단계에서는 실행 중인 메모리 목록에 추가해 기능을 먼저 검증한다.
- 파일 입출력 단계가 연결되면 정상 추가 직후 `state.json`에도 저장한다.
- 입력 도중 중단되면 불완전한 퀴즈를 저장하지 않는다.

### 퀴즈 목록

- 저장된 퀴즈를 카테고리별로 묶어 표시한다.
- 각 문제와 선택지를 확인할 수 있게 한다.
- 퀴즈가 없으면 별도 안내 후 메뉴로 돌아간다.

### 최고 점수

- 점수는 `round(정답 수 / 출제 수 * 100)`으로 계산한다.
- 기존 카테고리 점수보다 높을 때만 최고 점수를 갱신한다.
- 갱신한 점수는 즉시 `state.json`에 저장한다.
- 아직 플레이하지 않은 카테고리는 `기록 없음`으로 표시한다.

## 공통 입력과 안전 종료

- 입력 앞뒤의 공백을 제거한다.
- 빈 입력, 숫자 변환 실패와 범위 밖 입력은 안내 후 다시 받는다.
- 카테고리, 문제와 선택지에는 빈 문자열을 허용하지 않는다.
- 숫자가 필요한 메뉴, 답 선택과 정답 등록에 같은 검증 메서드를 사용한다.
- `KeyboardInterrupt`와 `EOFError`는 가능한 상태를 저장한 뒤 traceback 없이
  안내 메시지와 함께 종료한다.

## `state.json` 스키마

카테고리별 최고 점수를 사용하므로 단수 `best_score` 대신 일관되게
`best_scores`를 사용한다.

```json
{
  "quizzes": [
    {
      "category": "과학",
      "question": "문제 내용",
      "choices": ["선택지 1", "선택지 2", "선택지 3", "선택지 4"],
      "answer": 1
    }
  ],
  "best_scores": {
    "과학": 80
  }
}
```

- 프로젝트 루트를 기준으로 경로를 계산한다.
- UTF-8, `ensure_ascii=False`, 들여쓰기 2칸으로 저장한다.
- 임시 파일을 먼저 작성한 뒤 교체하여 부분 저장을 방지한다.
- 파일이 없으면 기본 퀴즈와 빈 최고 점수로 시작한다.
- JSON 문법이나 스키마가 손상되었으면 timestamp가 붙은 파일로 원본을
  백업한 뒤 기본 상태를 만든다.
- 백업에 실패하면 원본을 덮어쓰지 않고 메모리 상태로 실행한다.
- 읽기·쓰기 오류는 `try/except`로 처리하고 사용자에게 안내한다.
- 손상 파일 백업은 Git에 실수로 추가되지 않도록 제외한다.

## 단계별 구현과 Git 커밋

각 단계는 관련 자동 테스트와 수동 검증을 통과한 뒤 커밋한다. 한 번에 한
단계만 진행하며 push는 별도 요청 전까지 수행하지 않는다.

1. 계획 문서 저장
   - `Docs: 상식 퀴즈 구현 계획 정리`
2. 메뉴와 공통 입력
   - `Feat: 메뉴와 공통 입력 처리 구현`
3. `Quiz` 클래스와 카테고리 데이터 구조
   - `Feat: Quiz 클래스와 카테고리 구조 구현`
4. `feature/solving` 브랜치에서 카테고리별 플레이
   - `Feat: 카테고리별 퀴즈 플레이 구현`
5. `main`에 `--no-ff` 병합
6. 퀴즈 추가
   - `Feat: 퀴즈 등록 기능 구현`
7. 퀴즈 목록
   - `Feat: 퀴즈 목록 조회 기능 구현`
8. 카테고리별 최고 점수
   - `Feat: 카테고리별 최고 점수 구현`
9. `QuizGame` 책임 정리
   - `Refactor: QuizGame 기능별 책임 정리`
10. `state.json` 입출력 완성
    - `Feat: state.json 저장과 불러오기 구현`
11. 통합 예외와 안전 종료
    - `Fix: 입력 중단과 손상 데이터 복구 처리`
12. 통합 테스트와 영속성 검증
    - `Test: 필수 기능과 데이터 영속성 검증`
13. 사용자가 제공한 상식 퀴즈 5개 이상 반영
    - `Feat: 상식 퀴즈 기본 데이터 추가`
14. README와 제출 증거 정리
    - `Docs: README와 제출 증거 정리`

퀴즈 플레이 브랜치 작업 시 다음 명령을 사용한다.

```zsh
git status --short --branch
git checkout -b feature/solving
# 기능 구현, 검증과 커밋
git checkout main
git merge --no-ff feature/solving
git log --oneline --graph --decorate --all
```

`--no-ff`로 fast-forward가 가능한 경우에도 병합 커밋을 남긴다. 병합과
그래프를 확인하기 전에는 기능 브랜치를 삭제하지 않는다.

## 검증 계획

### 자동 검증

```zsh
python -m unittest discover -s tests -v
python -m compileall -q .
git diff --check
```

테스트 항목:

- `Quiz` 정상·비정상 생성과 JSON 변환
- 공백, 빈 입력, 문자와 범위 밖 숫자 재입력
- 카테고리 자동 생성과 중복 처리
- 선택한 카테고리의 문제만 순서대로 출제
- 0점, 부분 점수와 100점 계산
- 낮거나 같은 점수에서 최고 점수를 갱신하지 않음
- 퀴즈 추가 직후 저장
- 빈 목록과 아직 플레이하지 않은 점수 처리
- 파일 없음, 정상 JSON, 손상된 JSON 처리
- 한글 데이터와 재실행 영속성
- Ctrl+C와 EOF 안전 종료

### 수동 검증과 증거

- 메뉴 1~5와 잘못된 입력
- 기존·신규 카테고리 퀴즈 추가
- 퀴즈 목록, 정오답과 최종 결과
- 최고 점수 확인
- 종료 후 재실행 데이터 유지
- 손상 파일 백업과 기본 상태 복구
- Git 브랜치 분기와 `--no-ff` 병합 그래프

검증된 터미널 결과와 화면만 `evidence/`에 저장한다.
