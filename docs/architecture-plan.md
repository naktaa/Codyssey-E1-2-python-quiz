# 상식 퀴즈 게임 아키텍처 및 구현 계획

## 문서 목적

이 문서는 E1-2 상식 퀴즈 게임의 확정된 구조, 동작 기준, 구현 순서와
Git 커밋 경계를 기록한다. 실제 구현과 검증 결과가 이 계획과 달라지면
현재 코드와 실행 결과를 우선하고 관련 진행 문서를 갱신한다.

## 범위와 기본 결정

- 퀴즈 주제는 별도 카테고리 구분이 없는 상식 퀴즈다.
- 전체 문제에서 풀 개수를 선택하고 무작위로 출제한다.
- 최고 점수는 모든 플레이를 비교한 단일 0 이상의 정수로 저장한다.
- 실제 기본 문제는 여러 분야가 섞인 총 5개다.
- 외부 라이브러리 없이 Python 표준 라이브러리만 사용한다.
- `Test/time-limit`에서 문제별 20초 제한 시간과 10초 자동 힌트를 실험한다.
- 랜덤 출제, 문제 수 선택, 힌트, 퀴즈 삭제와 점수 히스토리는 사용자 승인 후
  `feature/bonus`에서 구현했으며 `main` 병합을 완료했다.

## 프로그램 구조

```text
main.py
   │
   ▼
src/game_manager.py
└── QuizGame
   ├── Quiz 객체 목록
   ├── 단일 최고 점수
   ├── 메뉴와 공통 입력
   ├── 플레이·추가·목록·점수
   ├── src/timed_input.py의 제한 시간 입력
   └── state.json 저장·불러오기
           │
           ├── 정상 데이터
           └── src/default_quizzes.py fallback
```

애플리케이션 코드는 `src/`에 둔다. `main.py`는 실행 명령을 단순하게 유지하기
위해 루트에 두고, 최종 `state.json`도 미션 요구사항에 따라 프로젝트 루트에 둔다.

### `main.py`

- 프로그램 진입점만 담당한다.
- `get_state_path()`로 실제·확인용 상태 경로를 선택한다.
- 확인용 모드이면 사용할 파일을 안내한다.
- `QuizGame` 객체를 만들고 `load_state()` 후 `run()`을 호출한다.

### `Quiz`

```python
Quiz(
    question: str,
    choices: list[str],
    answer: int,
    hint: str | None,
)
```

책임:

- 문제, 선택지 4개, 정답 번호와 힌트 보관
- 빈 문자열, 선택지 개수와 정답 범위 검증
- 문제와 선택지 출력
- 사용자 답의 정오답 확인
- `to_dict()`와 `from_dict()`를 통한 JSON 변환

검증 기준:

- 문제는 공백 제거 후 비어 있을 수 없고, 힌트가 있으면 같은 기준을 적용한다.
- 선택지는 정확히 4개이며 각 선택지는 비어 있을 수 없다.
- 정답은 1~4 범위의 정수다.

### `QuizGame`

주요 속성:

```python
quizzes: list[Quiz]
best_score: int | None
score_history: list[dict[str, str | int]]
state_path: Path
timed_input: TimedTerminalInput
```

주요 메서드:

- `run()`
- `show_menu()`
- `read_int()`
- `read_nonempty()`
- `read_yes_no()`
- `select_quiz_count()`
- `play_quizzes()`
- `add_quiz()`
- `list_quizzes()`
- `delete_quiz()`
- `show_best_score()`
- `record_game_result()`
- `show_score_history()`
- `show_score_records()`
- `load_state()`
- `save_state()`
- `validate_state_data()`
- `backup_corrupted_state()`
- `recover_corrupted_state()`
- `safe_exit()`

일반 게임 입출력은 터미널의 `input()`과 `print()`를 직접 사용한다. 제한 시간
답 입력은 `TimedTerminalInput`에만 분리하며 범용 입출력 주입은 사용하지 않는다.
확인은 `QUIZ_STATE_MODE=test`로 실제 `state.json`과 분리한다.

### `TimedTerminalInput`

- `select.select()`로 표준 입력과 다음 시간 이벤트를 한 루프에서 기다린다.
- `time.monotonic()` 기준으로 문제마다 20초를 새로 계산한다.
- 시작할 때 내용이 비어 있는 `힌트:` 전용 줄을 먼저 확보한다.
- 1초마다 현재 입력 줄을 지우고 `남은 시간 | 정답 번호`를 다시 그린다.
- 10초에는 커서 저장·복원 없이 한 줄 위의 전용 줄만 실제 힌트로 바꾸고
  즉시 한 줄 아래 입력 위치로 돌아온다.
- 비정규·비에코 입력 모드에서 입력 중인 문자를 내부 버퍼에 보존한다.
- 잘못된 답이 처음 제출되면 입력 줄 아래에 오류 전용 줄을 만들고, 이후 오류는
  새 줄을 추가하지 않고 같은 전용 줄에서 교체한다.
- 정답 제출·시간 초과·입력 중단 시 아래 오류 줄을 지우고 다음 출력 위치로 간다.
- 20초 시간 초과 시 `termios.tcflush()`로 남은 입력을 제거한다.
- macOS 터미널을 기준으로 하며 Windows 표준 입력 호환은 이번 범위에서 제외한다.

## 메뉴와 기능 흐름

```text
1. 퀴즈 풀기
2. 퀴즈 목록 보기
3. 최고 점수와 기록
4. 퀴즈 추가
5. 퀴즈 삭제
6. 종료
```

### 퀴즈 풀기

1. 저장된 전체 문제 수 안에서 풀 개수를 선택한다.
2. `random.sample()`로 선택한 개수만큼 중복 없이 뽑는다.
3. 반환된 무작위 순서대로 출제하며 원본 목록과 JSON 순서는 유지한다.
4. 문제마다 20초 카운트다운을 새로 시작한다.
5. 10초 전 정답은 3점, 10초에 힌트를 공개한 뒤 정답은 1점이다.
6. 오답 또는 20초 시간 초과는 0점으로 처리하고 다음 문제로 넘어간다.
7. 잘못된 형식의 입력은 남은 시간 안에서 다시 받고 타이머는 초기화하지 않는다.
8. 완료 후 정답 수, 자동 힌트 공개 횟수와 실제 획득 점수만 출력한다.
9. 단일 최고 점수를 비교하고 플레이 기록과 함께 저장한다.

퀴즈가 없으면 안내 후 메인 메뉴로 돌아간다.

### 퀴즈 추가

- 문제, 선택지 4개, 정답 번호와 문제별 힌트를 입력받는다.
- 모든 값이 정상일 때만 `Quiz`를 목록에 추가한다.
- 정상 추가 직후 활성 상태 파일에 저장한다.
- 저장에 실패하면 방금 추가한 퀴즈를 메모리에서도 제거해 추가 전체를 취소한다.
- 환경 변수 미지정 또는 `real` 모드에서는 `state.json`, `test` 모드에서는
  `state.test.json`을 사용한다.
- 입력 도중 중단되면 불완전한 퀴즈를 저장하지 않는다.

### 퀴즈 목록

- 선택지는 제외하고 전체 퀴즈의 번호와 질문만 연속해서 표시한다.
- 퀴즈가 없으면 별도 안내 후 메뉴로 돌아간다.

### 퀴즈 삭제

- 전체 퀴즈 목록에서 문제 번호를 선택한다.
- 선택한 문제 내용을 다시 표시하고 `y` 또는 `n`으로 삭제 여부를 입력받는다.
- 삭제를 확인한 경우에만 목록에서 제거하고 활성 상태 파일에 즉시 저장한다.
- 마지막 퀴즈가 삭제되면 단일 최고 점수도 `null`로 초기화한다.
- 파일 저장에 실패하면 메모리의 퀴즈와 최고 점수도 삭제 전 상태로 되돌린다.

### 최고 점수

- 문제별 획득 점수를 합산하고 만점은 `출제 문제 수 × 3점`으로 계산한다.
- 자동 힌트 공개 횟수는 정답 여부와 관계없이 10초가 지난 문제 수를 센다.
- 기존 단일 점수보다 높을 때만 최고 점수를 갱신한다.
- 갱신한 점수는 플레이 기록과 함께 활성 상태 파일에 즉시 저장한다.
- 아직 플레이하지 않았으면 `기록 없음`으로 표시한다.
- 이전 100점 환산 기록은 형식상 유효하므로 자동 변환하거나 삭제하지 않는다.
  이전 `best_scores`는 값 중 최댓값을 단일 `best_score`로 이전한다.

### 플레이 기록

- 플레이가 끝날 때 `record_game_result()`가 시각과 결과를 목록에 추가한다.
- 시각은 로컬 시스템 시간을 `YYYY-MM-DD HH:MM` 형식으로 저장한다.
- 점수·만점, 정답 수·문제 수와 자동 힌트 공개 횟수를 함께 저장한다.
- 최고 점수 갱신과 플레이 기록 추가는 `save_state()` 한 번으로 반영한다.
- JSON에는 모든 기록을 유지하고 화면에는 시각 기준 최근 5개의 획득 점수만
  최신순으로 표시한다. 같은 분의 기록은 나중에 추가된 기록을 먼저 표시한다.
- 퀴즈를 삭제해도 이미 완료한 과거 기록은 유지한다.

## 공통 입력과 안전 종료

- 입력 앞뒤의 공백을 제거한다.
- 빈 입력, 숫자 변환 실패와 범위 밖 입력은 안내 후 다시 받는다.
- 문제와 선택지에는 빈 문자열을 허용하지 않는다.
- 숫자가 필요한 메뉴, 답 선택과 정답 등록에 같은 검증 메서드를 사용한다.
- 제한 시간 답은 별도 입력 루프에서 1~4를 검증하며 잘못 입력해도 남은 시간을
  이어서 사용한다.
- 삭제 확인은 공백과 대소문자를 정리한 `y/n` 공통 입력 메서드로 처리한다.
- `KeyboardInterrupt`와 `EOFError`는 가능한 상태를 저장한 뒤 traceback 없이
  안내 메시지와 함께 종료한다.

## `state.json` 스키마

카테고리를 사용하지 않으므로 최고 점수는 단수 `best_score`로 저장한다.

```json
{
  "quizzes": [
    {
      "question": "문제 내용",
      "choices": ["선택지 1", "선택지 2", "선택지 3", "선택지 4"],
      "answer": 1,
      "hint": "문제에 맞는 힌트"
    }
  ],
  "best_score": 7,
  "score_history": [
    {
      "played_at": "2026-08-05 21:34",
      "score": 4,
      "max_score": 6,
      "correct_count": 2,
      "total_count": 2,
      "hint_count": 1
    }
  ]
}
```

- 프로젝트 루트를 기준으로 경로를 계산한다.
- 기본값과 `QUIZ_STATE_MODE=real`은 `state.json`, `QUIZ_STATE_MODE=test`는
  Git에서 제외한 `state.test.json`을 사용한다.
- UTF-8, `ensure_ascii=False`, 들여쓰기 2칸으로 저장한다.
- 임시 파일을 먼저 작성한 뒤 교체하여 부분 저장을 방지한다.
- 파일이 없으면 기본 퀴즈와 빈 최고 점수로 시작한다.
- 기존 파일에 `score_history`가 없으면 빈 목록으로 불러온다.
- 이전 카테고리 스키마의 `category`는 읽을 때 무시하고, `best_scores` 값 중
  최댓값을 `best_score`로 이전한 뒤 다음 저장부터 새 스키마를 사용한다.
- JSON 문법이나 스키마가 손상되었으면 timestamp가 붙은 파일로 원본을
  백업한 뒤 기본 상태를 만든다.
- 백업에 실패하면 원본을 덮어쓰지 않고 메모리 상태로 실행한다.
- 읽기·쓰기 오류는 `try/except`로 처리하고 사용자에게 안내한다.
- 손상 파일 백업은 Git에 실수로 추가되지 않도록 제외한다.

### 오류 원인 메시지

- `validate_state_data()`는 최상위 객체, `quizzes`, `best_score`,
  `score_history`와 점수 형식에 대해 코드에 정의된 `ValueError` 메시지를
  발생시킨다.
- `Quiz.from_dict()`와 `Quiz.__post_init__()`은 개별 퀴즈의 필수 필드,
  문자열·선택지·정답 형식 오류 메시지를 담당한다.
- `load_state()`는 위 오류를 잡아 `상태 파일이 손상되었습니다: {오류}` 형식으로
  출력한 뒤 복구를 시작한다.
- JSON 문법 오류의 세부 내용은 표준 라이브러리 `json`의
  `JSONDecodeError`, 파일 입출력 오류 내용은 `OSError.strerror`에서 가져온다.

## 단계별 구현과 Git 커밋

각 단계는 사용자 직접 실행과 필요한 증거를 확인한 뒤 커밋한다. 한 번에 한
단계만 진행하며 push는 별도 요청 전까지 수행하지 않는다.

1. 계획 문서 저장
   - `Docs: 상식 퀴즈 구현 계획 정리`
2. 메뉴와 공통 입력
   - `Feat: 메뉴와 공통 입력 처리 구현`
3. `Quiz` 클래스와 카테고리 데이터 구조
   - `Feat: Quiz 클래스와 카테고리 구조 구현`
4. `feature/solving` 브랜치에서 카테고리별 플레이
   - `Feat: 카테고리별 퀴즈 플레이 구현`
5. `main`에 `--no-ff` 병합
6. 퀴즈 추가
   - `Feat: 퀴즈 등록 기능 구현`
7. 퀴즈 목록
   - `Feat: 퀴즈 목록 조회 기능 구현`
8. 카테고리별 최고 점수
   - `Feat: 카테고리별 최고 점수 구현`
9. `QuizGame` 책임 정리
   - `Refactor: QuizGame 기능별 책임 정리`
10. `state.json` 입출력 완성
    - `Feat: state.json 저장과 불러오기 구현`
11. 통합 예외와 안전 종료
    - `Fix: 입력 중단과 손상 데이터 복구 처리`
12. 직접 실행과 영속성 검증
    - `Docs: 필수 기능과 데이터 영속성 검증 기록`
13. 사용자가 제공한 상식 퀴즈 5개 이상 반영
    - `Feat: 상식 퀴즈 기본 데이터 추가`
14. README와 제출 증거 정리
    - `Docs: README와 제출 증거 정리`
15. `feature/bonus`에서 문제 수·랜덤·힌트·삭제·히스토리 구현
    - 기능별 `Feat`·`Refactor` 커밋
16. 사용자가 보너스 브랜치를 `main`에 병합
17. 카테고리를 제거하고 단일 상식 퀴즈·직접 입출력 구조로 단순화
    - `8f5b8b7 Refactor: 카테고리 분류 제거`
18. `Test/time-limit`에서 20초 제한 시간·10초 자동 힌트 실험
    - `Feat: 제한 시간과 자동 힌트 기능 실험`
19. 최종 직접 실행, Git 그래프와 clone·pull 증거 정리

```zsh
git checkout main
git merge --no-ff feature/solving
git log --oneline --graph --decorate --all
```

`--no-ff`로 fast-forward가 가능한 경우에도 병합 커밋을 남긴다. 병합과
그래프를 확인하기 전에는 기능 브랜치를 삭제하지 않는다.

## 검증 계획

### 사용자 직접 실행과 증거

- 메뉴 1~6과 잘못된 입력
- 새 상식 퀴즈 추가
- 질문만 표시하는 퀴즈 목록
- 문제 수 선택, 무작위 출제, 20초 초기화, 자동 힌트별 점수와 최종 결과
- 한 줄 카운트다운과 시간 초과 후 다음 문제 입력 분리
- 최고 점수와 최근 플레이 기록 5개 확인
- `y/n` 퀴즈 삭제와 취소
- 종료 후 재실행 데이터 유지
- 손상 파일 백업과 기본 상태 복구
- 필수·JSON·보너스 브랜치 분기와 `main` 병합 그래프

검증된 터미널 결과와 화면만 `evidence/`에 저장한다.

### 문서·정적 확인

- `git status --short --branch`로 브랜치와 변경 파일 확인
- `git log --oneline --graph --decorate --all`로 실제 Git 이력 확인
- `git diff --check`로 문서와 코드의 공백 오류 확인
- import 목록으로 Python 표준 라이브러리만 사용하는지 확인

정적 확인은 실행 기능의 정상 증거를 대신하지 않는다. 기능 완료 표시는 사용자가
`main.py`를 직접 실행한 원본 로그나 캡처와 연결한다.
