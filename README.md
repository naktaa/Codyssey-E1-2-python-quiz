# E1-2 나만의 퀴즈 게임

> 현재 상태: `Test/time-limit` 브랜치에서 문제별 20초 제한 시간,
> 1초 단위 카운트다운과 10초 후 자동 힌트를 완성했다. 사용자 직접 확인과
> 회귀 검사를 통과했으며 `main` 병합을 준비하고 있다.

## 프로젝트 개요

터미널 메뉴에서 상식 퀴즈를 풀고, 새 문제를 추가하고, 문제 목록과 최고 점수와
최근 기록을 확인하는 Python 콘솔 프로그램이다. 퀴즈, 단일 최고 점수와 전체
플레이 기록은 프로젝트 루트의 JSON 파일에 저장한다.

## 퀴즈 주제와 선정 이유

- 주제: 다양한 분야를 섞은 상식 퀴즈
- 선정 이유: 별도 분류 선택 없이 바로 여러 분야의 상식을 확인하기 위함
- 현재 데이터: 과학·역사 분야가 섞인 총 5개의 기본 상식 문제

## 개발 환경과 실행 방법

- macOS / zsh
- Python 3.12.13 (요구 버전 3.10 이상)
- Git 2.53.0
- 외부 라이브러리 없음

실제 게임 데이터인 `state.json`을 사용한다.

```zsh
python3 --version
python3 main.py
```

직접 기능을 확인하면서 실제 게임 데이터를 바꾸고 싶지 않을 때는 다음처럼
환경 변수로 확인용 상태 파일을 선택한다.

```zsh
QUIZ_STATE_MODE=test python3 main.py
```

이 모드는 `[테스트 모드] state.test.json을 사용합니다.`를 먼저 출력하고
프로젝트 루트의 `state.test.json`만 읽고 쓴다. 이 파일과 복구 과정에서 생기는
`*.corrupt-*` 파일은 `.gitignore`에 포함되어 기능 확인 중의 데이터 변경이
커밋에 들어가지 않는다. 환경 변수를 지정하지 않거나 `real`로 지정하면
`state.json`을 사용한다.

| 플레이 기록 | 완료 시각과 결과를 전부 저장하고 최근 5개를 최신순 표시 | 구현 완료, 최종 증거 필요 |
| JSON 불러오기 | 정상 데이터를 `Quiz`, 최고 점수와 플레이 기록으로 복원 | 새 스키마 확인 완료, 최종 증거 필요 |

| 손상 복구 | 오류 안내, 원본 백업, 기본 데이터 복구 | 직접 실행 캡처·백업 내용 확보 |
| 안전 종료 | 정상 종료·Ctrl+C·EOF에서 저장 후 안내 | 직접 실행 로그·캡처 확보 |

## 주요 코드 구조와 메서드

- `main.py`: 실행 모드에 맞는 상태 경로를 정하고 `QuizGame.load_state()` 후
  `QuizGame.run()`을 호출한다.
- `src/quiz.py`의 `Quiz`: 문제 데이터 검증, `display()`, `is_correct()`,
  `to_dict()`, `from_dict()`를 담당한다.
- `src/game_manager.py`의 `QuizGame`: 입력과 메뉴, 플레이, 추가, 목록, 점수,
  저장·불러오기와 복구 흐름을 관리한다.
- `src/timed_input.py`의 `TimedTerminalInput`: `select`로 답 입력과 시간 이벤트를
  함께 기다리고, 카운트다운·자동 힌트·시간 초과 입력 제거를 담당한다.
- `select_quiz_count()`: 저장된 전체 문제 수를 안내하고 풀 문제 수를
  공통 숫자 입력 검증으로 받는다.
- `random.sample()`: 원본 퀴즈와 JSON 순서는 유지하면서 이번 플레이에 사용할
  문제를 중복 없이 선택하고 반환된 무작위 순서대로 출제한다.
- `TimedTerminalInput.read_answer()`: 문제마다 20초 동안 답을 기다리고 10초 후
  힌트를 자동 공개한다. 빈 입력·문자·범위 밖 숫자는 남은 시간 안에서 다시 받는다.
- `add_quiz()`: 새 퀴즈를 메모리에 추가한 뒤 JSON 저장에 성공한 경우에만 추가를
  확정한다. 저장에 실패하면 메모리에서도 제거해 파일과 실행 상태를 일치시킨다.
- `read_yes_no()`: 대소문자 구분 없이 `y` 또는 `n`이 입력될 때까지 다시 받는다.
- `delete_quiz()`: 전체 목록에서 문제를 선택하고 확인된 삭제만 파일에 반영한다.
- `record_game_result()`: 완료 시각과 결과를 기록하고 최고 점수와 함께 저장한다.
- `show_score_history()`: 전체 기록 중 플레이 시각 기준 최근 5개를 출력한다.
- `show_score_records()`: 메뉴 3번에서 최고 점수와 최근 기록을 이어서 보여준다.
- `save_state()`: 퀴즈, 점수와 플레이 기록을 임시 JSON 파일에 쓴 뒤 상태 파일로
  교체해 부분 저장 가능성을 줄인다.
- `validate_state_data()`: JSON 최상위 구조, 퀴즈 목록과 점수 값을 검증한다.
- `backup_corrupted_state()`: 손상 원본을 timestamp가 붙은 이름으로 복사한다.
- `recover_corrupted_state()`: 백업 성공 후에만 기본 데이터로 활성 상태 파일을
  다시 만든다. 백업이 실패하면 원본 보호를 위해 해당 실행의 저장을 막는다.
- `safe_exit()`: 정상 종료와 입력 중단 시 가능한 현재 상태를 저장하고 종료한다.

일반 메뉴 입력은 `input()`과 `print()`를 직접 사용한다. 제한 시간 답 입력만
`TimedTerminalInput`으로 분리해 범용 `input_func`·`output_func` 주입을 되살리지
않았다. macOS 터미널에서는 `select`, `time.monotonic`, 비정규 입력 모드와
`termios.tcflush()`를 사용한다. 카운트다운은 현재 입력 줄만 다시 그리며,
힌트 공개 시에만 한 줄 위의 전용 `힌트:` 줄을 교체하고 즉시 입력 줄로 돌아온다.
입력 중인 내용은 내부 버퍼에 보관하므로 두 갱신 중에도 유지된다. 잘못된 답은
처음 발생할 때 입력 줄 아래에 오류 전용 줄을 만들고 이후에는 같은 줄을 교체한다.

### 퀴즈 추가 저장 실패 롤백

퀴즈 추가 기능을 검토하면서, 메모리 목록에 새 퀴즈를 추가한 뒤 JSON 저장이
실패하면 메모리와 파일의 상태가 달라질 수 있음을 확인했다. 파일 권한이나 저장
경로 문제로 `save_state()`가 실패하면 현재 실행에서는 새 퀴즈가 보이지만,
재실행 후에는 파일에 없는 퀴즈가 사라질 수 있다.

이를 예방하기 위해 저장 실패 시 방금 추가한 퀴즈를 메모리 목록에서도 제거하는
롤백 처리를 적용했다. 따라서 JSON 저장에 성공한 경우에만 퀴즈 추가가 확정되며,
저장 결과와 사용자에게 보이는 실제 추가 결과가 일치한다. 이 내용은 실제 장애
발생 기록이 아니라 코드 검토에서 발견한 위험을 사전에 보완한 사항이다.

## 점수 계산

- 문제 시작 후 10초 전에 맞히면 3점이다.
- 10초에 힌트가 자동 공개되며, 이후 20초 전에 맞히면 1점이다.
- 오답이나 20초 시간 초과는 0점이며 바로 다음 문제로 넘어간다.
- 잘못된 형식의 입력은 시간을 초기화하지 않고 남은 시간 안에서 다시 받는다.
- 한 게임의 만점은 `출제 문제 수 × 3점`이다.
- 결과 화면에는 정답 수, 자동 힌트 공개 횟수와 실제 획득 점수만 표시한다.
- 최고 점수는 모든 상식 퀴즈 플레이 중 가장 높은 점수를 저장한다. 선택한 문제 수가
  달라도 원점수를 그대로 비교한다. 적은 문제를 선택하면 얻을 수 있는 최대
  점수도 낮아지므로 높은 최고 기록을 갱신하기 어려워진다.
- 이전 카테고리 스키마의 `best_scores`는 불러올 때 가장 높은 값을 단일
  `best_score`로 이전한다.
- 플레이 완료 시 `YYYY-MM-DD HH:MM` 시각, 점수·만점, 정답 수,
  문제 수와 자동 힌트 공개 횟수를 기록한다. JSON에는 전체 기록을 보관하고 화면에는
  가장 최근 기록 5개의 획득 점수만 표시한다.

## 데이터 영속성

### 실제 게임 데이터

- 파일: 프로젝트 루트의 `state.json`
- 용도: 실제 퀴즈 목록, 단일 최고 점수와 전체 플레이 기록
- Git: 미션 산출물이므로 추적
- 저장 시점: 퀴즈 추가·삭제 직후, 플레이 결과·최고 점수 기록 직후,
  정상·중단 종료 시

### 직접 확인용 데이터

- 파일: 프로젝트 루트의 `state.test.json`
- 선택 방법: `QUIZ_STATE_MODE=test`
- 용도: 실제 게임 데이터를 바꾸지 않는 사용자 직접 실행 확인
- Git: 변경이 반복되므로 추적하지 않음

### 영속성 검증 상태

- JSON 적용 전: 추가한 문제가 재실행 후 사라지는 메모리 동작을
  [비교 기준 로그](evidence/logs/memory-persistence-test.md)로 보존했다.
- JSON 적용 후 코드: 퀴즈 추가·삭제와 플레이 결과 기록 시 파일 저장, 시작 시
  퀴즈·최고 점수·플레이 기록 불러오기가 연결되어 있다.
- JSON 적용 후 최고 점수: 이전 100점 환산 방식에서 과학 100점을 저장하고
  종료한 뒤 같은 확인용 파일로 재실행해 100점이 복원되는 것을
  [원본 로그](evidence/logs/persistence-restart.md)로 확인했다.
- JSON 적용 후 추가 퀴즈: 추가·종료·재실행 후 목록에 남는 원본 로그는 아직
  확보하지 않았다. 이 항목까지 확인하기 전에는 전체 영속성 완료로 표시하지 않는다.
- 보너스 영속성: 삭제 결과와 최근 플레이 기록의 재실행 유지 증거는 최종 기능
  확인 때 함께 확보한다.

## JSON 스키마

```json
{
  "quizzes": [
    {
      "question": "문제 내용",
      "choices": ["선택지 1", "선택지 2", "선택지 3", "선택지 4"],
      "answer": 1,
      "hint": "문제에 맞는 힌트"
    }
  ],
  "best_score": 7,
  "score_history": [
    {
      "played_at": "2026-08-05 21:34",
      "score": 4,
      "max_score": 6,
      "correct_count": 2,
      "total_count": 2,
      "hint_count": 1
    }
  ]
}
```

`quizzes`는 퀴즈 객체 목록이고 `best_score`는 `null` 또는 0 이상의 정수인 단일
최고 점수다. `question`은 비어 있지 않은 문자열,
`choices`는 정확히 4개의 문자열, `answer`는 1~4 정수여야 한다. 새 퀴즈의
`hint`는 비어 있지 않은 문자열이며, 기존 JSON에 필드가 없으면 기본 문제는
기본 데이터의 힌트를 연결하고 그 밖의 기존 문제는 힌트 없음 상태로 읽는다.
`score_history`는 완료된 플레이 기록 목록이다. 이전 JSON처럼 이 필드가 없으면
빈 목록으로 불러오고, 다음 저장부터 필드를 추가한다.

이전 카테고리 JSON도 바로 손상 처리하지 않는다. 퀴즈와 플레이 기록의
`category`는 읽을 때 무시하고, `best_scores`의 값 중 최댓값을 `best_score`로
사용한다. 다음 저장부터 위의 단일 상식 퀴즈 스키마로 기록한다.

## 손상 파일 복구

손상된 JSON이나 잘못된 스키마를 발견하면 원인을 출력하고, 원본을
`상태파일명.corrupt-YYYYMMDD-HHMMSS-ffffff`로 복사한 뒤 기본 퀴즈와 빈
최고 점수·플레이 기록으로 활성 상태 파일을 복구한다.

사용자가 확인용 파일의 `quizzes` 키를 `quizes`로 바꿔 직접 실행했을 때
`quizzes는 목록이어야 합니다.`가 출력됐고,
`state.test.json.corrupt-20260805-181939-287895`가 만들어진 뒤 기본 데이터로
복구됐다. 캡처와 해당 백업 파일의 실제 내용은
[JSON 복구 연결 기록](evidence/logs/json-recovery.md)에서 함께 확인할 수 있다.
